# 문체, 용어 규칙 (판 6, 2026-11-26)

판 3(2026-11-11) 규칙에 사용자가 직접 고친 방식(2026-11-26, 이유 확인)을 더한 판. 이 문서도 가운뎃점을 쓰지 않는다.

## 한 겹
화면이 곧 읽을 거리다. 발표자가 말할 것만 `note`.

| 자리 | 문체 | 길이 |
|---|---|---|
| 꼬리표 | 명사구. 묶음, 주제, 기준, 단위 | 묶음 10자, 주제 25자 안 |
| 헤드메시지 | 보고서체 「~함, ~임, ~됨, ~있음」. 대상(끝까지) + 숫자(조건 괄호) + 의미 | 2줄 50~90자(띄어쓰기 뺌) |
| 벤토 제목 | 결론 문장 2줄 + 부제목에 범위와 기준 | 줄마다 18자 안팎 |
| 도식 칸, 카드 | 제목 명사구 + 설명 한두 줄 보고서체 | 칸 안에 넘치지 않게 |
| 각주 | 「주: 1) … 2) …」 「출처: 기관 자료(코드), … (기준일 기준)」 | 2줄 안 |

## 6판 고친 방식 (사용자가 고친 판과 대조하고 이유를 물어 확인한 것)
1. **가운뎃점(·)을 쓰지 않는다.** 꼬리표, 범례, 짧은 이름표 나열, 「선행, 동행지수」 같은 묶음 용어까지 모두 쉼표나 조사(와, 과). 칸 구분은 빗금이나 세로줄. 절을 잇는 쉼표는 줄이고 「-고, -며」로. 이유: 회사 보고 장표 관례, 글자 수 줄이기, 가운뎃점이 읽기 불편. (점검 `가운뎃점`, 고치기 `ecs.py fixdots`)
2. **前 / 現 표기.** 전후 비교는 「前 주문 시스템 / 現 주문 시스템」처럼. 美, 韓, 對 같은 다른 한자 약어도 **허용**(의무 아님, 기존 글을 일괄로 바꾸지 않음). (점검 `前/現`, 확인할 것)
3. **기호.** 「3분의 1」 → ⅓, 「이름: 풀이」, A+B, 성명/주민번호. (점검 `분수 기호`)
4. **대상 이름은 끝까지, 읽는 사람의 업무 용어로.** 「시스템」 → 「주문 처리 시스템」. 한 일보다 바뀐 결과가 보이는 이름. 이유: 읽는 사람이 아는 말, 무엇을 가리키는지 분명하게.
5. **통용 영어는 그대로.** 실제 회의와 메일에서 쓰는 말(Local PC, Pipeline, API)을 억지로 풀지 않는다. ECOM 장표에도 적용(판 3의 「데이터 → 자료」 규칙은 삭제).
6. **확정 안 된 계획은 쓰지 않는다.** 「진행할 예정임」 대신 지금 상태(「검토 중임」). 설정값에는 이유를 함께(「동시 2건이 최대(3건이면 메모리 부족)」). (점검 `확정 안 된 계획`)
7. **숫자에는 측정 조건을, 변화에는 원인을 괄호로.** 「API로 호출한 결과(요청 2건 동시 처리 기준)」. 읽는 사람이 되물을 것을 문장 안에서 먼저 답한다.
8. **머리글과 꼬리표에 대분류 번호와 여러 단계 경로를 쓰지 않는다.** 장의 주제만. 보조 정보는 본문보다 한 단계 작은 글자. 한 덱의 머리글 양식은 하나로. (점검 `꼬리표 번호`, `꼬리표 경로`)
9. **파일 경로와 파일 이름을 쓰지 않는다.** (점검 `경로`)

## 7판 고친 방식 (CW49 검토 49건, 2026-11-27 이유를 물어 확인한 것)
10. **헤드메시지는 값 나열 말고 뜻.** 「138달러까지 올랐고 91달러로 내려옴」 대신 「변동폭이 컸음」, 「~가 자리 잡았음」. 이유: 숫자 받아쓰기는 메시지가 아님(사용자 답 「값 나열 말고 뜻」).
11. **세부는 본문으로.** 연도 네 개, 사례 목록을 헤드에 늘어놓지 않고 차트, 도식에 둔다. 이유: 「세부는 본문으로」.
12. **단서는 각주로.** 「공식 자료로 확인되지 않음」 같은 주의 사항은 헤드가 아니라 각주. 헤드는 그 장의 핵심 구조(예: 「페트로 달러 구조가 이때 잡힘」). 이유: 「단서는 각주로」.
13. **통용어를 쓰고 만든 말 금지.** 오일 쇼크, 페트로 달러, 「중동 국가 중」. 「세 갈래」「짚은 나라」「이어진 길」 같은 AI 말투 금지. 이유: 「통용어, 생소한 말 금지」. (lint 사전에 더함)
14. **헤드의 숫자, 시점, 주장은 본문에 모두 보여야 한다.** 헤드에 쓴 고점 날짜, 「생산 1위 미국」, 「2022.07 6.33%」가 차트에 없으면 안 됨. 차트는 작성일 최신 값까지. 이유: 헤드와 본문이 안 맞으면 청자가 근거를 못 찾음(사용자 지적 1, 28, 30, 41번).
15. **각주 번호는 본문에 표시가 있을 때만.** 「1) 2)」를 쓰면 본문 해당 자리에 같은 번호를 단다. 기준 연도, 기관이 다른 두 값을 나란히 두면 기준을 맞추거나 다름을 그 자리에 밝힌다. 이유: 「1)2)가 어디있어」(23번).
16. **출처 자리.** 출처는 각주나 문장 끝 괄호. 카드 머리, 제목 자리에 매체 이름을 두지 않는다(제목처럼 읽힘). 「메르 블로그 인용」 같은 출처 표시는 본문에 드러내지 않고 각주에만(21, 36번).
17. **시사점은 2~3개 이상.** 하나뿐이면 시사점 칸을 두지 않거나 더 찾는다(38번).
18. **청자가 모르는 이름엔 주체와 까닭을.** 「12일 전쟁」 → 이스라엘(+미국) 대 이란, 핵시설 공격. 차이를 보이면 까닭도(나라마다 재정균형유가가 다른 이유)(20, 26번).
19. **장 사이 논리를 잇는다.** 앞 장 결론과 부딪치는 장(매장 1위 미국 생산 뒤 사우디 강조)은 왜 보여주는지 헤드에 밝힌다. 전제가 필요한 장은 전제부터(두바이 역전 전에 아시아 원유 수입 출처)(29, 38번).
20. **숫자 묶음은 연결고리가 있어야 한다.** 여는 숫자 칸(무슬림 인구, 매장량, 통과량, 유가)이 서로 이어지지 않으면 연결 화살과 문장을 넣거나 뺀다(1번).
21. **표지 부제는 덱 흐름의 큰 주제어.** 「종파와 나라」 같은 추상어 대신 「이슬람의 역사, 페트로 달러, 이란 전쟁」(2번).
22. **토의는 고를 것을 준다.** 손들기 대신 예상 답 고르기, 찬반. 주요 논의 사항은 무엇을 논의하는지 문장으로(45, 46번).
23. **지적은 덱 전체에.** 한 장에 받은 지적은 같은 문제가 있는 다른 장(부록 포함)에도 같은 기준으로 고치고, 보고에 「지적 외에 같은 기준으로 고친 장」을 따로 적는다. 이유: 사용자 「내가 지적한거 다른 장표들에도 적용되면 동일하게 적용해줘」.

## 말투, AI 말투 금지(lint 사전)
- **낱말 조각** : 어미를 잘라 만든 「~ 좁힘, ~ 먼저, ~ 봄, 함께 인하」 → 「한국 인상에 따른 금리차 축소, 한국 선제 인상, 한미 동반 인하」.
- **비유어** : 꼭대기, 고원, 방아쇠, 체력, 웃돈, 무게, 길, 온도 → 고점, 지속, 요인, 성장 여력, 프리미엄(정의 후), 수준.
- **안내, 꾸밈 말** : 쉽게 말해, 한 줄로, 핵심은, 결국, 사실상, 주목할 점은 → 지움.
- **따옴표로 만든 말** : 「누가 더 오래 올리나」 → 「양국의 인상 지속 기간」.
- **시스템 설명 줄** : 「○○건, 카톡에」 같은 도구 설명 금지.
- 표준 경제 용어(역전, 금리차, 동결, 빅스텝, 전년동월비, 순유출)와 보고서체를 쓴다.

## 숫자 쓰기
- 천 단위 쉼표, 단위 붙임(3,406.6억 달러, 1,337.4원, 4.01%). 음수는 「−」(U+2212).
- 비율 %, 차이 %p, 배수 배. 금리 수준 소수 두 자리(3.00%).
- 기간 「2023.07~2024.08」, 달 「2026.08」, 날 「11.26」.
- 위첨자 각주 번호 ¹⁾ ²⁾ ³⁾ → 각주 「1) …」.

## 용어 정제
- `terms/glossary.json` 의 같은 말 묶음에서 대표 낱말만(전년동월비 ← YoY, 전년 대비).
- 영어 약어는 첫 등장에 풀이 : FOMC(연방공개시장위원회). 길면 부록 용어 장으로.
- 개발자 말은 풀어 쓴다(인사이트 → 시사점). 단 업무에서 그대로 쓰는 영어는 5번 규칙대로 둔다.

## 구조화 점검 (표와 글 나열을 도식 후보로 알림, 모두 확인할 것)
| 점검 | 걸리는 때 | 바꿀 후보 |
|---|---|---|
| 작은 표 | 3줄 이하, 3칸 이하 표 | 카드 열(`cards`), 가운데 축 비교(`compare`) |
| 글 속 화살표 | 한 장의 짧은 글에 → 4개 이상 | 차례 띠(`steps`), 상자 + 연결선(`nodes`) |
| 글 나열 | 짧은 글 5개 이상 목록(points 등) | 카드 열, 타일(`tiles`) |
| 조건 문장 | 「~이면, ~일 경우」 3곳 이상 | 갈림 도식(`nodes` 이름표 연결선) |
| 숫자 많은 글 | 글 위주 장에 숫자 3개 이상 | 숫자 칸(`stat`), 막대(`bars`) |

## 고친 글 반영 절차
1. 사용자가 덱 글을 직접 고친 판을 주면 `ecs.py textdiff <초안 deck.json> <고친 deck.json>` 으로 장별 바뀐 글을 뽑는다.
2. 바뀐 것을 묶음(같은 방식끼리)으로 나눠 AskUserQuestion 으로 이유를 묻는다. 고른 답만 적고 이유를 추정하지 않는다.
3. 이 문서 「6판 고친 방식」에 새 번호로 더하고, 점검할 수 있는 것은 `ecs.py` 문체 사전(style6)에 넣는다. 아래 「개정 기록」에 날짜와 묶음을 적는다.

## 하지 말 것
- 투자 권유처럼 읽히는 말(「사야 함」, 「오를 것」).
- 기사 문장 그대로 옮기기(요약 + 출처).
- 출처 없는 숫자, 지어낸 예시 숫자.
